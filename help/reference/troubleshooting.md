# 疑难解答 {#troubleshooting}

>[!IMPORTANT]
>
>[!DNL Adobe LLM Apps]当前在Beta中。
>
>此处显示的功能、工作流和UI不一定表示产品的最终状态。 要加入Beta，请发送电子邮件至llm-apps-beta@adobe.com 。

从观察到的症状开始。 进行故障排除时，请勿共享凭据、令牌、专用MCP URL或敏感处理程序结果。

## 应用程序创建和操作生成

| 症状 | 尝试什么 |
|---------|-------------|
| Adobe托管基础架构设置失败 | 在&#x200B;**设置失败**&#x200B;下读取错误，然后选择&#x200B;**重试**。 如果页面无法检查进度，请选择&#x200B;**再次检查**；后台将继续安装 |
| 没有可用的AEM程序 | 请求管理员获取项目访问权限。 如果加载失败，请选择&#x200B;**重试加载程序** |
| 新存储库不显示 | 使用&#x200B;**连接其他存储库**&#x200B;授予Adobe LLM应用程序GitHub应用程序访问权限，返回到向导，并选择&#x200B;**刷新组织和存储库** |
| 操作或构件存储库验证失败 | 使用兼容的现有项目或空存储库。 为操作和小组件使用单独的存储库，然后再次选择&#x200B;**验证存储库** |
| 未检测到AEM代码同步 | 为构件存储库安装AEM代码同步，在其确认页面上将自己添加为站点管理员，返回到向导，然后选择&#x200B;**验证AEM代码同步安装** |
| 创建应用程序时没有生成操作 | 应用程序创建仅设置基础结构。 在应用程序页面上，选择&#x200B;**自动生成操作**，输入&#x200B;**您的网站**，然后选择&#x200B;**生成我的操作**。 查看[创建操作](/help/guides/creating-actions.md) |
| 操作仍在生成 | UI预计生成最多需要30分钟。 在操作页面上跟踪进度，或离开页面并稍后返回 |
| 操作生成报告失败 | 确认该网站是通过HTTPS公开的，并且对于您自己的存储库，存储库访问权限仍然有效。 如果问题仍然存在，请联系Beta团队并提供显示的错误消息 |

## 操作和处理程序

| 症状 | 尝试什么 |
|---------|-------------|
| 未调用操作 | 在对话中启用应用程序的插件或连接器。 确认在操作设置中向AI模型&#x200B;**公开，且应用程序页面上的操作**&#x200B;可见性&#x200B;**开关已打开。**&#x200B;改进描述并重新部署元数据更改 |
| 空响应或错误响应 | 运行`npm test`，然后使用MCP检查器或`curl`调用处理程序。 查看[本地处理程序开发和测试](/help/reference/development.md) |
| 处理程序在本地工作，但在部署后无法正常工作 | 检查最新的推送提交，确认运行时配置，并验证操作代码标识符是否与`actions/<code-identifier>/index.js`匹配 |
| 无法将生成的操作标记为已审阅 | 确认已成功生成处理程序和构件。 检查生成的拉取请求是否存在合并冲突，重新加载操作，然后再次选择&#x200B;**标记为已审核** |

## 小组件

| 症状 | 尝试什么 |
|---------|-------------|
| 构件未呈现 | 验证脚本URL、构件URL、HTTPS、EDS发布、CSP域和CORS标头 |
| 构件将呈现，但不显示数据 | 使用MCP检查器调用处理程序，并将其`structuredContent`形状与从`bridge.toolResult`读取的字段进行比较 |
| 构件在直接预览中起作用，但在ChatGPT中不起作用 | 直接预览可能使用示例数据。 测试已部署的处理程序结果并验证CORS和CSP是否允许EDS源 |
| 浏览器请求被阻止 | 仅将所需源添加到正确的CSP字段并重新部署 |
| HTTP标头编辑器无法保存配置 | 使用[AEM配置服务](https://aem.live/docs/config-service-setup)或要求EDS管理员初始化站点标头配置 |

当完整的`bridge.toolResult`值可能包含个人或敏感数据时，请勿记录这些值。

## 部署

| 症状 | 尝试什么 |
|---------|-------------|
| 在&#x200B;**准备**&#x200B;期间部署失败 | 验证处理程序存储库是否已链接，并且您的Adobe Developer Console访问权限仍然有效 |
| 在&#x200B;**生成应用程序**&#x200B;期间部署失败 | 在本地运行`npm install`、`npm test`和`npm run build`。 修复依赖关系、语法或测试故障并推送更改 |
| 部署成功，但缺少更改 | 确认预期的提交已推送，并重新部署到同一环境 |
| 操作仍为&#x200B;**未部署** | 查看操作或更改其元数据后再次部署 |

## 身份验证 {#authentication}

在&#x200B;**[!UICONTROL 启用身份验证]**&#x200B;开启时应用。 查看[使用您自己的身份提供程序对最终用户进行身份验证](/help/guides/authentication.md)。

| 症状 | 尝试什么 |
|---------|-------------|
| 保存设置后，操作仍为公共操作 | 再次将应用程序部署到该环境。 身份验证更改将在下次部署时生效 |
| 切换环境后设置看起来错误 | 确认&#x200B;**[!UICONTROL Workspace]**&#x200B;选取器显示您想要的环境。 **[!UICONTROL 暂存]**&#x200B;和&#x200B;**[!UICONTROL 生产]**&#x200B;是独立配置的 |
| 登录未开始 | 确认您在启用身份验证后部署了应用程序，并且该操作使用&#x200B;**[!UICONTROL 必需]**。 **[!UICONTROL Optional]**&#x200B;操作仅在它的处理程序要求登录时提示 |
| 平台将用户发送到错误的登录页面 | 验证&#x200B;**[!UICONTROL 颁发者]**&#x200B;是否与您的身份提供程序的颁发者URL完全匹配，以及它是否可以通过公共HTTPS访问 |
| 登录成功，但每个调用仍被拒绝 | 确认您的身份提供程序颁发了令牌，这些令牌的受众是相应环境的应用程序MCP服务器URL，并且该令牌是使用非对称算法签名的JWT。 查看[令牌要求](/help/reference/authentication-reference.md#token-requirements) |
| 身份提供程序从不接收任何流量 | 您的提供商的发现、授权和令牌端点必须通过公共HTTPS访问。 检查防火墙、WAF或它前面的IP允许列表 — 您的应用程序可以在您的提供商无法访问时访问 |
| 身份提供程序拒绝为所请求的受众颁发令牌 | 某些提供程序只为已向其注册的资源颁发令牌。 确认应用程序的MCP服务器URL已注册为身份提供程序中的资源标识符 |
| 登录时未请求新添加的范围 | LLM平台会将应用程序的已发布元数据缓存几分钟。 请稍候，然后重试登录 |
| 要求用户再次登录作用域 | 该操作需要令牌未携带的作用域。 在身份提供程序中将范围添加到客户端的授予中，或从操作中删除该范围 |
| 用户会收到重复的登录提示 | 在每次调用时返回`extra.challengeAuth()`而不检查调用方的身份请求在验证后再次登录的处理程序。 仅当缺少操作所需的身份时请求身份验证 |
| 在用户到达您的身份提供程序之前，登录将被拒绝 | LLM平台发送的重定向URI未向授权服务器注册。 某些平台会为每个连接器颁发一个不同的值，因此请注册连接器设置屏幕上显示的值 |
| 保存被阻止，显示不支持的范围消息 | 将作用域添加到&#x200B;**[!UICONTROL 支持的作用域]**，或从需要它的操作中删除它 |
| 公共操作仍会提示登录[!DNL Claude] | 检查连接器是否在需要时使用&#x200B;**[!UICONTROL 登录]**，而不是&#x200B;**[!UICONTROL 立即登录]**。 对于较早部署的应用程序，请更新运行时并重新部署。 当前运行时上的混合应用程序可匿名调用公共操作 |
| **[!UICONTROL 可选]**&#x200B;操作返回登录文本，但没有Claude登录提示 | `extra.challengeAuth()`是ChatGPT工具结果挑战。 对于可移植登录门，请使用&#x200B;**[!UICONTROL Required]**&#x200B;操作，以便运行时返回Claude预期的HTTP挑战 |
| 即使每个操作都是&#x200B;**[!UICONTROL 无]**，应用程序仍会提示登录 | 关闭&#x200B;**[!UICONTROL 启用身份验证]**&#x200B;并进行部署。 打开时，即使未对操作设置限制，应用程序也会通告授权服务器 |

请勿将访问令牌、声明集或身份提供程序客户端密钥粘贴到支持请求中。

## ChatGPT插件

| 症状 | 尝试什么 |
|---------|-------------|
| 插件未出现 | 打开[chatgpt.com/plugins](https://chatgpt.com/plugins)，确认您的帐户或工作区允许自定义MCP服务器，然后安装或连接生成的插件 |
| 插件创建失败 | 从&#x200B;**再次复制完整的HTTPS MCP服务器URL测试应用程序**&#x200B;并选择与应用程序匹配的身份验证方法。 仅对公共应用程序使用&#x200B;**无身份验证**，而不是作为失败的OAuth的解决方法 |
| 插件可连接，但无法调用操作 | 确认该插件已附加到聊天，操作已公开到模型，并且已部署最新版本 |
| 插件使用了错误的环境 | 使用预期的暂存或生产MCP服务器URL编辑或重新创建插件 |
| 插件仍显示旧的操作元数据 | 部署更改，在ChatGPT连接上选择&#x200B;**刷新**，然后启动新对话 |

如果问题仍然存在，请在联系Beta团队之前记录应用程序名称、环境、失败的步骤、时间和显示的错误消息。 请勿包含机密或敏感的客户数据。
